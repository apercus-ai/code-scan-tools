# 扫描 Rubric

修改本文件后同步更新 `code-scan/skills/code-scan/SKILL.md` 与脚本 prompt 中的对应措辞。

## 维度

### 质量 `quality`

查：
- 可读性：命名、函数长度、嵌套深度、魔法数
- 边界处理：空值、越界、异常路径
- 一致性：与仓库现有模式冲突的写法
- 错误处理：吞异常、错误信息缺失

证据门槛：引用具体文件行，说明"为什么是问题"，不接受"看起来不好"。

### 冗余 `dead-code`

查：
- 死代码：不可达分支、未使用导出/函数/类型
- 重复实现：跨模块的近似逻辑
- 未使用依赖

证据门槛：优先用工具找候选：
- JS/TS：`npx knip`、`npx jscpd`
- Python：`vulture`、`radon`
- Rust：`cargo udeps`、`clippy`

工具不可用时只做代码阅读，并在 `notCovered` 说明"未运行工具"。

### 性能 `perf`

查：
- 算法复杂度（O(n²) 循环、嵌套遍历）
- N+1 查询、循环内 I/O
- 无谓分配/拷贝、重复序列化

证据门槛：**必须给复杂度论证或基准数据**。没有证据的性能建议不报。

## 严重度

| 级别 | 标准 |
|---|---|
| `high` | 数据丢失、崩溃、错误结果 |
| `medium` | 明显缺陷、显著性能退化、维护成本高 |
| `low` | 风格、小优化 |

## 复核规则

- 每条发现交给独立复核员（全新上下文），只凭证据复现
- 复现成功 → `verified`；失败 → `unconfirmed`（保留，不删除）
- 复核员不编辑文件
